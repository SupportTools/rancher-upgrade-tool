# data/

## `catalog.json` — live

What the service loads at startup. Generated by `cmd/update-matrix`, validated on
load, and the service **refuses to start** if it is malformed.

Do not hand-edit it. Run the generator and review the pull request it opens, which
carries a journey diff describing what changed for real queries.

## `upgrade-paths.json` — superseded, and DO NOT DELETE

The pre-rewrite dataset. Nothing reads it at runtime, and it is deliberately not
copied into the container image.

**It is kept because most of it cannot be recovered.** 63 of its 70 Rancher entries
are not re-derivable from upstream:

- `endoflife.date` publishes only the **latest patch per cycle**, not every patch.
- SUSE **retires** old per-version support-matrix pages. Fetching them during the
  migration returned 404 for `rancher-v2-5-17` and `rancher-v2-3-11`.

And the detail matters: supported Kubernetes ranges **vary between patch releases
within a minor**. The 2.5 line alone has 13 distinct range signatures across its 17
patches. That per-patch fidelity is exactly what someone stuck on an old Rancher
needs, and this file is the only remaining record of it.

This is why `cmd/update-matrix` **extends** the catalog rather than regenerating it.
A from-scratch regeneration would silently flatten every old version to its cycle's
latest patch.

`scripts/migrate-upgrade-paths.py` documents the transformation that produced the
first `catalog.json` from this file.
